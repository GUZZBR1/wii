# Repository Guidelines

## Project Structure & Module Organization

Wii Web Sports Arena — a Vite + React 19 + TypeScript browser arcade (running and tennis) controlled by body pose via webcam. No backend; deploy is a static `dist/` on Vercel.

- `src/cv/` — pose pipeline: `pose.worker.ts` (MediaPipe Pose Landmarker Lite in a module Web Worker, `useModule: true`, GPU→CPU fallback), `poseClient.ts` (warm-worker lifecycle: `init` / `beginCapture` / `pauseCapture` / `dispose`, one frame in flight), `calibrator.ts`, `oneEuroFilter.ts`, `protocol.ts` (worker message + snapshot types).
- `src/kinematics/` — pure, testable detectors over `PoseSnapshot`: tracking gate, cadence, jump, lane lean, swing; `actionPipeline.ts` turns snapshots into `SportActionEvent`s.
- `src/games/` — `core/GameLoop.ts` (fixed 1/60 timestep, Three.js renderer, disposal helpers) plus `track/` and `tennis/` scenes decoupled from the camera.
- `src/ui/` — `GameCanvas` (lazy-loads a game per sport), `CameraPip` (video PiP + overlay + calibration buttons), `PoseOverlay` (2D skeleton draw).
- `tests/` — Vitest; synthetic pose fixtures and deterministic detector tests.
- `scripts/` — `copy-mediapipe-wasm.mjs` (prebuild/predev): pins tasks-vision version, copies only the **module** WASM variant into `public/mediapipe/wasm-<version>/`, verifies the model SHA-256 against `SHA256SUMS` and that `src/cv/mediapipeAssets.ts` constants match (version-addressed URLs make `immutable` caching safe).
- `public/mediapipe/` — pose model (`pose_landmarker_lite.<sha8>.task`, tracked — filename carries its hash) + WASM files (gitignored, generated by the script).
- `docs/` — analysis notes, e.g. `docs/analise-de-gargalos.md` (bottleneck audit).

## Build, Test, and Development Commands

```bash
npm ci            # install (Node 24 LTS / npm 11, see .nvmrc)
npm run dev       # vite dev server (predev copies MediaPipe WASM)
npm test          # vitest run
npm run build     # tsc -b && vite build
npm run preview   # serve dist/
npm run lint      # biome lint .
npm run format    # biome format --write .
```

Camera access needs HTTPS in production; `localhost` works in dev. Keyboard controls work without a camera.

## Coding Style & Naming Conventions

- TypeScript strict (`tsconfig.json`); Biome 2.x is the linter/formatter (`biome.json`) — run `npm run lint` before committing.
- Detectors in `src/kinematics/` must stay pure (no DOM/Three.js imports) so tests keep working with synthetic fixtures.
- Game code owns its Three.js objects: dispose via `disposeObjectTree` (`src/games/core/GameLoop.ts`).
- Worker protocol changes go through `src/cv/protocol.ts` — keep `WorkerRequest`/`WorkerReply` and `PoseSnapshot` in sync with `pose.worker.ts` and `poseClient.ts`.
- TypeScript modules are camelCase (`poseClient.ts`, `trackScore.ts`); classes and React components are PascalCase (`PoseClient`, `GameCanvas.tsx`, `TrackGame.ts`). Scripts, docs, and config files are kebab-case (`copy-mediapipe-wasm.mjs`).

## Testing Guidelines

- `npm test` runs `tests/**/*.test.ts` under Vitest (node environment). Add a test for every new detector behavior or gameplay rule change.
- The CV worker path has no automated coverage — `vite` serves a real browser worker; verify camera flow manually (`npm run dev` → ATIVAR CÂMERA → TRACKING).

## Commit & Pull Request Guidelines

Short imperative subjects (`Add initial project structure`), one logical change per commit. PRs explain the change and motivation, link issues when available, and list the commands run for verification.

## Security & Configuration

- Video is processed on-device; nothing is uploaded. The MediaPipe runtime may phone performance metrics to Google — disclosed in README/THIRD_PARTY_NOTICES.
- No secrets in this repo. Machine-specific config belongs in `~/.config`, never in project files.
